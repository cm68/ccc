# CPP - C Preprocessor

A standalone C preprocessor that produces a compact binary lexeme stream (`.x`) and human-readable preprocessed output (`.i`). Designed for the ccc compiler project with emphasis on minimal memory footprint.

## Overview

The preprocessor performs full C preprocessing including:
- Macro definition and expansion (#define, #undef)
- Conditional compilation (#if, #ifdef, #ifndef, #elif, #else, #endif)
- File inclusion (#include)
- Comment stripping (C and C++ style)
- Tokenization with keyword recognition

## Command Line

```bash
cpp [options] <source.c>
```

**Options:**
- `-o <base>` - Output base name (produces `<base>.x`; `<base>.i` with `-p`)
- `-I<dir>` - Add user include directory
- `-i<dir>` - System include directory (default: `/usr/include` or `libsrc/include`)
- `-D<name>[=val]` - Define macro (defaults to value `1` if no `=val`)
- `-p` - Also emit a human-readable `<base>.i` (forks `xdump`)
- `-E` - Preprocess and dump readable output to stdout (forks `xdump`)
- `-N` - Suppress line markers (`LINENO`/`NEWLINE`) in the `.x` stream

**Output Files:**
- `<base>.x` - Binary lexeme stream for pass1 compiler (always written)
- `<base>.n` - Id-to-name sidecar for the interned identifiers (always written)
- `<base>.i` - Human-readable preprocessed source (only with `-p`; rendered by `xdump`)

The `.x` stream is the real output; the `.i` form is produced by decoding `.x`
with `xdump`, not written directly by the preprocessor. Identifiers travel in
`.x` as 2-byte ids and their spellings live in the `.n` sidecar — see
[OUTPUT.md](OUTPUT.md) §4 for the format. This is the only format; there is no
flag to turn it off.

## Architecture

### Processing Pipeline

```
Source File → Character Stream → Lexer → srcget → norm walker → emitStructTok → .x
      ↑                          lex.c   tdsrc.c    norm.c        emit.c
Include Files                            (+knr.c file scope, cfold.c folds)
Macro Expansions
```

The normalizer is a **recursive-descent walker**, `norm.c`: the C call stack
carries the nesting that the old filter pipeline kept in hand-rolled context
stacks. It pulls tokens through `srcget()` and pushes the normalized stream
straight to `emitStructTok()`. The transforms are:

- **source layer** (`tdsrc.c`, `srcget`) — enum lowering (constants become
  macro-table entries, the type becomes `unsigned char`) and typedef
  dissolution. What the walker pulls is already free of `ENUM`, `TYPEDEF`,
  and every typedef name.
- **file scope** (`norm.c`, `norm_run`) — passes through untouched except
  struct/union bodies (skipped verbatim) and K&R function normalization
  (`knr.c`).
- **statements** (`norm.c`, `stmt`, at brace depth > 0) — local declaration
  initializer splitting, synthetic braces on unbraced control bodies, loop
  lowering to labels and gotos, `break`/`continue` → `goto`.
- **constant folding** (`cfold.c`) — `sizeof` and folded constant expressions
  are answered on the spot from size registries the walker feeds; the same
  climber evaluates `#if`.

See [NORM.md](NORM.md) for the walker's structure and [OUTPUT.md](OUTPUT.md)
for the resulting output-language guarantees.

### Program Flow (cpp.c)

```c
main() {
    1. addDefine("z80=1")      // the target name, as zc3 predefines it
    2. Parse command-line arguments
    3. Create output files: <base>.x, and name <base>.i / <base>.n
    4. Add include paths (current directory first, then -I paths)
    5. filterInit()            // == norm_init()
    6. Call process(sourcefile)
    7. internWrite(<base>.n)   // the id-to-name sidecar
    8. If -p/-E: fork/exec xdump to render/dump the .i form
}

process(sourcefile) {
    1. pushfile(sourcefile)    // Push source onto textbuf stack
    2. ioinit()                // Prime lexer with first two characters
    3. emitFileStart()         // Emit initial LINENO marker
    4. gettoken(); gettoken(); // Fill cur and next tokens
    5. norm_run()              // The walker runs to EOF, pushing to emit
    6. emitflstr()             // Release a string literal still held back
    7. Brace-balance check, then emit final E_O_F token
}
```

# Lexeme Stream Format (.x file)

The lexeme stream is a flat sequence of tokens in program order, terminated by a
single `E_O_F` (0x00) byte. It is **raw little-endian binary** — token codes are
the values defined in [`lexeme.h`](lexeme.h) and shared verbatim with pass1, and
multi-byte fields are emitted as raw bytes (not ASCII hex).

> **Authoritative spec:** the complete token-code tables, payload encodings, and
> line-marker rules live in [OUTPUT.md](OUTPUT.md). This section is a summary;
> if the two ever disagree, OUTPUT.md wins.

## Token Encoding Summary

| Token Type | Code | Format |
|------------|-----:|--------|
| Simple | (self) | 1 byte: the token code from `lexeme.h` |
| Number (`NUMBER`) | 21 | code + 4-byte LE integer |
| String (`STRING`) | 22 | code + 2-byte LE len + bytes |
| Int-typed number (`INUMBER`) | 23 | code + 4-byte LE integer (folded, types as `int`) |
| Long number (`LNUMBER`) | 25 | code + 4-byte LE integer (source said `L`) |
| Symbol id (`SYMID`) | 26 | code + 2-byte LE id; spelling in the `.n` sidecar |
| Label id (`LABELID`) | 27 | code + 2-byte LE id; spelling in the `.n` sidecar |
| Line marker (`LINENO`) | 116 | code + 2-byte LE line + 1-byte namelen + name |
| Newline (`NEWLINE`) | 117 | 1 byte: "advance current line by 1" |
| Asm string (`ASMSTR`) | 118 | code + 2-byte LE len + bytes |
| Keyword | 128–160 | 1 byte: keyword code from `lexeme.h` |
| EOF (`E_O_F`) | 0 | single `0x00` byte, ends the stream |

`SYM` (20) and `LABEL` (112) are the *names* of these tokens on the pass1 side;
cpp always emits the interned id forms `SYMID`/`LABELID` instead. Code 23 was
once `FNUMBER`; ccc has no floating point, and the slot now carries `INUMBER`.
Codes 130/131 (`FLOAT`/`DOUBLE`) are deliberately vacant — `float` and `double`
are not reserved words, so a program may typedef them.

Simple tokens cover delimiters (`SEMI`=1, `BEGIN`=2, …), operators
(`PLUS`=40, `ASSIGN`=80, `ARROW`=50, …), and keywords (`INT`=128, `IF`=147, …).
`SIZEOF_KW` is normalized to `SIZEOF` (91) on emission, and `CONST`/`VOLATILE`
are silently dropped. All values are in `lexeme.h`.

## Worked Example

Source code:
```c
int x = 42;
```

Emitted `.x` bytes (line markers omitted for clarity):
```
80            INT           (128)
1a 01 00      SYMID  #1     (26, id 1 little-endian; "x" is in the .n sidecar)
50            ASSIGN        (80)
15 2a 00 00 00  NUMBER 42   (21, value 0x0000002a little-endian)
01            SEMI          (1)
00            E_O_F         (0)
```

Note `NUMBER 42` is five raw bytes (`15 2a 00 00 00`) — the tag plus a 4-byte
little-endian value. It is **not** the tag followed by ASCII hex digits. The
real bytes for a lowered `while` loop can be inspected with
`od -An -tx1 <file>.x`; a decoded rendering is in `test/while.expected`.

# Preprocessor Directives

## #define

### Object-like Macros

```c
#define NAME value
#define NAME          // Defines as empty (or "1" from -D flag)
```

### Function-like Macros

**Critical:** The `(` must immediately follow the name with NO whitespace:

```c
#define FOO(a,b) a+b     // Function-like: FOO(1,2) -> 1+2
#define BAR (x)          // Object-like: BAR -> (x)
```

### Special Operators

**Stringify (#):** Converts parameter to string literal
```c
#define STR(x) #x
STR(hello)    // -> "hello"
```

**Token Paste (##):** Concatenates adjacent tokens
```c
#define CONCAT(a,b) a##b
CONCAT(foo,bar)   // -> foobar
```

### Line Continuation

```c
#define LONG_MACRO(x) \
    if (x) \
        do_something()
```

## #include

```c
#include <stdio.h>    // System: search sysIncPath first, then -I paths
#include "myheader.h" // User: search -I paths only (current dir first)
```

**Search order for `<file.h>`:**
1. System include path (`-i` flag or default)
2. User include paths (`-I` flags, in order)

**Search order for `"file.h"`:**
1. Current directory (empty path added first)
2. User include paths (`-I` flags, in order)

## Conditional Compilation

```c
#if EXPR
#ifdef NAME        // True if NAME is defined
#ifndef NAME       // True if NAME is NOT defined
#elif EXPR         // Else-if (can have multiple)
#else              // Else (only one allowed)
#endif             // End conditional block
```

**Expression operators supported:**
- Arithmetic: `+`, `-`, `*`, `/`, `%`
- Comparison: `<`, `>`, `<=`, `>=`, `==`, `!=`
- Logical: `&&`, `||`, `!`
- Bitwise: `&`, `|`, `^`, `~`, `<<`, `>>`
- Parentheses: `(`, `)`

**defined() pseudo-function:**
```c
#if defined(DEBUG) && !defined(NDEBUG)
#if defined(__GNUC__)
```

**Undefined identifiers evaluate to 0:**
```c
#if UNDEFINED_MACRO    // Evaluates to #if 0
```

## #undef

```c
#undef NAME    // Removes macro definition (silently succeeds if not found)
```

# Data Structures

## struct token (cpp.h:96)

The current and next token during lexing:

```c
struct token {
    token_t type;           // Token type (single byte)
    int lineno;             // line where the token was scanned
    char *filename;         // file where the token was scanned
    union {
        long numeric;       // NUMBER/INUMBER/LNUMBER: integer value
        char *name;         // SYM/LABEL: interned identifier (canonical ptr)
        cstring str;        // STRING/ASMSTR: counted string (len + data)
    } v;
};
```

The per-token `lineno`/`filename` are what let the walker synthesize tokens and
still stamp them with the right source position — see NORM.md's
"Output-byte discipline". Names are **interned**: `intern()` returns one
canonical pointer per unique string, so `tokcpy` is a flat field copy and no
stage owns a name.

**Global instances:**
- `cur` - Current token being processed
- `next` - Lookahead token

## struct macro (cpp.h:171)

Macro definition storage:

```c
struct macro {
    unsigned char parmcount;   // 0 = object-like, >0 = function-like
    char *name;                // Macro name
    char **parms;              // Parameter names array (function-like only)
    char *mactext;             // Replacement text
    struct macro *next;        // Linked list
};
```

**Global list head:** `macros`

## struct textbuf (cpp.h:157)

Unified buffer for files and macro expansions:

```c
struct textbuf {
    char fd;                  // File descriptor (-1 = macro buffer)
    char *name;               // Filename or macro name
    char *storage;            // Buffer data
    short offset;             // Current read position
    short valid;              // Total valid bytes in buffer
    short lineno;             // Current line number
    char saved_column;        // Parent's column (for restoration)
    struct textbuf *prev;     // Stack pointer
};
```

**Stack top:** `tbtop`

## struct cond (cpp.h:182)

Conditional compilation state:

```c
struct cond {
    unsigned char flags;
#define C_TRUE      0x01      // Current block is active
#define C_ELSESEEN  0x02      // #else already seen
#define C_TRUESEEN  0x04      // At least one branch was true
    struct cond *next;        // Stack for nesting
};
```

**Stack top:** `cond`

## struct pendbuf / struct tokarray (cpp.h:127, 133)

The two token containers left from the filter era, both in `filtutil.c`:
`pendbuf` is a circular pending queue — there is exactly one, the typedef
layer's expansion output — and `tokarray` is a growable linear array used
wherever the walker has to collect tokens before it knows what they are.
Both grow by `GROWSTEP` (16) rather than doubling, because the Z80 build's
peak is measured in hundreds of bytes.

# I/O System (io.c)

## Character Stream Interface

The preprocessor maintains a two-character lookahead:

- `curchar` - Current character being processed
- `nextchar` - Next character (lookahead)
- `column` - Column position of curchar
- `lineno` - Current line number

## Textbuf Stack

Files and macro expansions share a unified stack:

```
┌─────────────────┐
│ Macro expansion │ ← tbtop (current)
├─────────────────┤
│ Include file    │
├─────────────────┤
│ Main source     │
└─────────────────┘
```

### pushfile(name)

Opens main source file and pushes onto stack:
1. Open file
2. Allocate textbuf with TBSIZE (1024) buffer
3. Push onto stack
4. Set filename/lineno globals

### insertfile(name, sys)

Opens include file with path search:
1. For `<file>`: Try sysIncPath first
2. Search include paths in order
3. Push onto stack
4. Initialize curchar/nextchar from new file
5. Fatal error if not found

### insertmacro(name, macbuf)

Inserts macro expansion into stream:

**Optimization:** If expansion fits in already-read portion of current buffer:
1. Copy text before current offset
2. Back up offset
3. Update curchar/nextchar

**Otherwise:**
1. Allocate new textbuf with fd=-1
2. Duplicate macro text as storage
3. Push onto stack

### advance()

Core I/O function - advances character stream:

```
1. Move nextchar → curchar
2. If buffer has more data: read nextchar
3. If buffer exhausted and file open: refill buffer
4. If file exhausted or macro empty: pop textbuf
5. Update line/column tracking
6. If curchar == 0 from macro end: goto step 1
```

**State restoration on pop:**
- Restore parent's column position
- Restore parent's line number
- Restore parent's filename
- Read nextchar from parent buffer

## Output

`outbufWrite()` in io.c writes straight to `lexFd`. An output-buffer stack
(`outbufPush`/`outbufPop`/replay, with spill-to-tempfile) used to live here for
deferred emission during loop lowering, but nothing ever pushed onto it: all
reordering happens above emit, in the walker. It has been removed; the
function name is what is left of it.

# Lexer (lex.c)

## Token Recognition

The lexer (`gettoken()`) recognizes:

1. **Comments** - Stripped before tokenization
   - C-style: `/* ... */`
   - C++ style: `// ...`

2. **Preprocessor directives** - `#` at column 0
   - Dispatched to `doCpp()`
   - Non-column-0 `#` is a token

3. **Identifiers/Keywords**
   - `issym()` extracts identifier
   - `kwlook()` checks keyword tables
   - Keywords become their token type
   - Non-keywords become SYM tokens

4. **Numbers**
   - Decimal: `123`
   - Hexadecimal: `0x1a`, `0X1A`
   - Octal: `0755`
   - Binary: `0b1010`, `0B1010`
   - Character: `'a'`, `'\n'`
   - An `L`/`l` suffix makes the token `LNUMBER` — that suffix is the only
     thing that can make a constant long, since everything downstream sizes a
     constant by magnitude.
   - Float literals (`3.14`, `1.0e10`) are **scanned and rejected**: ccc has no
     floating point, so `isnumber()` consumes the literal, raises `ER_C_CD`,
     and yields 0.

5. **Strings** - `"..."`
   - Escape sequences processed
   - Stored as counted strings

6. **Operators**
   - Single: `+ - * / % & | ^ < > ! ~ ? : = .`
   - Doubled: `++ -- || && == >> <<`
   - With `=`: `+= -= *= /= %= &= |= ^= >= <= != >>= <<=`
   - Arrow: `->`

## Keyword Tables (kw.c)

Compressed tables using a custom encoding:

```
Grammar:
  0xff <token>       - End: return token if string at null
  0xfe <token>       - End or continue: return token or advance
  <char>             - Literal: must match exactly
  <char|0x80> <skip> - Branch: match or skip bytes
```

Example from `cppkw[]`:
```c
'd'|HI, 7, 'e', 'f', 'i', 'n', 'e', 0xff, DEFINE,
//  ↑     └──────────────────────────┘
//  │              "define"
//  └── Skip 7 bytes if 'd' doesn't match
```

## Escape Sequences

Supported in character and string literals:

| Escape | Value | Description |
|--------|-------|-------------|
| `\n` | 0x0a | Newline |
| `\r` | 0x0d | Carriage return |
| `\t` | 0x09 | Tab |
| `\b` | 0x08 | Backspace |
| `\f` | 0x0c | Form feed |
| `\v` | 0x0b | Vertical tab |
| `\e` | 0x1b | Escape (extension) |
| `\\` | 0x5c | Backslash |
| `\'` | 0x27 | Single quote |
| `\"` | 0x22 | Double quote |
| `\0` - `\7` | octal | Octal (up to 3 digits) |
| `\xNN` | hex | Hexadecimal |
| `\BNN` | binary | Binary (extension) |
| `\DNN` | decimal | Decimal (extension) |

## ONELINE Mode

Used for `#if`/`#elif` expression evaluation:

- Enabled via `tflags |= ONELINE`
- Newline translates to `;` token
- Expression parser stops at `;`
- Prevents expressions spanning multiple lines

# Macro Expansion (macro.c)

## Expansion Process

1. **Lookup:** `maclookup(name)` searches linked list
2. **Arguments:** For function-like macros, parse `(arg1, arg2, ...)`
   - Track parenthesis nesting
   - Copy string/char literals verbatim
3. **Substitution:** Walk macro text, replace parameters
   - `#param` → `"arg"` (stringify)
   - `##` → removed (tokens concatenated)
   - `param` → `arg` (direct substitution)
4. **Insertion:** `insertmacro()` pushes expansion
5. **Recursion:** Nested macros expanded when inserted text is tokenized

## Argument Parsing

```c
#define FOO(a, b) ...
FOO(x + y, bar(1, 2))
//  └─┬─┘  └───┬───┘
//    a        b
```

- Parentheses tracked for nested calls
- Commas inside parens don't split arguments
- String/char literals copied without processing

## Example Expansion

```c
#define MAX(a, b) ((a) > (b) ? (a) : (b))

MAX(x, y+1)
```

Expansion steps:
1. Parse args: `a = "x"`, `b = "y+1"`
2. Substitute in `((a) > (b) ? (a) : (b))`
3. Result: `((x) > (y+1) ? (x) : (y+1))`
4. Insert into character stream
5. Lexer tokenizes the expansion

# Normalization

The normalizer sits between the lexer and the emitter, transforming the token
stream before output. It is a **recursive-descent walker** (`norm.c`) over a
source layer (`tdsrc.c`) that has already dissolved enums and typedefs. The
sections below describe the transformations by effect; for the walker's
structure, its output-byte discipline, and its memory profile see
[NORM.md](NORM.md).

## K&R to ANSI Conversion

Transforms old-style K&R function definitions to ANSI style:

```c
// K&R style input:
int foo(a, b, c)
int a;
char *b;
long c;
{ ... }

// ANSI style output:
int foo(int a, char *b, long c)
{ ... }
```

Parameters without explicit type declarations default to `int`.

## Brace Insertion

Every unbraced control-structure body gains synthetic braces — `if`, `else`,
and the bodies of the loops before they are lowered:

```c
// Input:
if (x > 0) x = 1;
if (x) foo(); else bar();

// Output:
if (x > 0) { x = 1; }
if (x) { foo(); } else { bar(); }
```

An if-body's closing `}` is **deferred**: it must precede an `else` either
way, so it is synthesized only after the token following the body has been
pulled and shown whether an `else` is there. Else-if chains continue without
an extra brace level.

## Loop Lowering

Transforms while/for/do loops into equivalent if/goto/label sequences. This eliminates
loop constructs entirely, so pass1 only needs to handle `if` and `goto` for control flow.

The lowered sequence is **spliced in place** — no extra `{ }` wrapper is added
around it — and every `LABEL` is emitted with a following `;` so it always
precedes a statement.

**WHILE loop:**
```c
while (cond) body
// becomes:
__W1T: ; if (!(cond)) { goto __W1B ; } body goto __W1T ; __W1B: ;
```

**FOR loop:**
```c
for (init; cond; incr) body
// becomes:
init ; __F1T: ; if (!(cond)) { goto __F1B ; } body
__F1C: ; incr ; goto __F1T ; __F1B: ;
```

**DO-WHILE loop:**
```c
do body while (cond);
// becomes:
__D1T: ; body __D1C: ; if (cond) { goto __D1T ; } __D1B: ;
```

**SWITCH** passes through unchanged and simply gains a trailing break label,
`__S<n>B: ;`.

An **empty clause emits nothing**: `for (;;)` and `while ()` produce no entry
test at all, so the loop is unconditional, and a `for` with no init or no
increment omits that fragment.

**Label naming:** `__<P><n><S>` where P is `W`/`F`/`D`/`S` and S is:
- `T` - Top of loop (condition test)
- `C` - Continue target (`F`/`D` only; `__D<n>C` precedes the do test so
  `continue` re-tests it, as C requires)
- `B` - Break target (after the loop)

**Break/Continue:** Resolved to goto statements targeting the innermost
matching label:
- `break;` → `goto __<P><n>B;` (P may be `S` — a `break` in a switch)
- `continue;` → `goto __W<n>T;` (WHILE) or `goto __<P><n>C;` (FOR/DO)

## Local Declaration Initializer Splitting

Splits local variable declarations with initializers into a declaration
followed by assignment statements. The whole declarator list is emitted first,
then the assignments in order:

```c
// Input:
void foo(void) {
    int x = 5, y = f();
    char *p = "hello";
}

// Output:
void foo(void) {
    int x, y;
    x = 5;
    y = f();
    char *p;
    p = "hello";
}
```

**Statics and arrays keep their initializers inline** — a `static int n = 3;`
or an `int a[] = {1,2};` must still be initialized at its declaration, so the
split does not apply.

This simplification allows pass1 to handle declarations uniformly without
tracking initializer expressions during declaration parsing.

## Typedef Dissolution and Enum Lowering

These happen in the **source layer** (`tdsrc.c`, `srcget`), below the walker.
What the walker pulls is already free of `ENUM`, `TYPEDEF`, and every typedef
name — so a declaration is recognisable from its leading token, and pass1
parses without a symbol table.

**Typedefs are dissolved, not tracked.** A typedef is a declarator with a hole
where the name sits; a use composes the use-site declarator into the hole and
the expansion is pushed through the one pending queue left in cpp (`tdq`).
Typedef'd struct bodies stream one member per pull so the queue stays small.

```c
typedef int error_t;
void gripe(error_t code) { ... }  // emitted as: void gripe(int code)
```

**Enum constants are glorified `#define`s.** Each goes into the macro table as
its value — globally visible, textual, exactly like `#define` — the enum type
itself rewrites to `unsigned char`, and a bare enum declaration vanishes. The
consequence for input source is real: an enum constant's name must not be
reused as any other identifier later in the file.

## Constant Folding

`cfold.c` keeps size and type registries fed by the walks `norm.c` is already
doing, and answers `sizeof` on the spot: aggregate layouts are packed and
byte-aligned, arrays multiply, unions take the max — pass1's `typesize`
arithmetic, computed early so a `sizeof` folds to a number before pass1 exists.
Anything the registries cannot price goes downstream unfolded, where pass1
still answers it. A folded constant that C types as `int` is emitted as
`INUMBER` rather than `NUMBER`, so pass1 types it by declaration rather than by
magnitude. The same expression climber evaluates `#if` (`parseConst`).

# Conditional Compilation

## State Machine

```
                    #if (true)
    ┌─────────────────────────────────────┐
    │                                     ▼
  START ──#if(false)──► FALSE_BLOCK ──#endif──► DONE
    │                       │
    │                       ├──#elif(true)──► TRUE_BLOCK
    │                       │
    │                       └──#else──► TRUE_BLOCK
    │
    └──#if(true)──► TRUE_BLOCK ──#endif──► DONE
                        │
                        ├──#elif──► FALSE_BLOCK (C_TRUESEEN)
                        │
                        └──#else──► FALSE_BLOCK (C_TRUESEEN)
```

## Flag Semantics

| Flag | Meaning |
|------|---------|
| `C_TRUE` | Current block is active (emit tokens) |
| `C_TRUESEEN` | At least one branch was true |
| `C_ELSESEEN` | `#else` already seen (error if another) |

## False Block Handling

When `!(cond->flags & C_TRUE)`:
- Only process conditional directives
- Skip `#define`, `#include`, `#undef`
- Skip all other tokens via `skiptoeol()`
- Nested `#if` blocks tracked correctly

# Limits and Constraints

| Constant | Value | Where | Description |
|----------|-------|-------|-------------|
| `TBSIZE` | 256 | cpp.h | Text buffer size. Was 512 to match the Micronix disk block; halved because three files open at a header closure's peak is 768 bytes of heap on the machine where cpp itself must fit. Half-block reads cost a few syscalls and no correctness. |
| `MACBUF` | 512 | cpp.h | Macro line/expansion buffer |
| `STRBUFSIZE` | 256 | cpp.h | String/symbol/identifier buffer |
| `MAXPARMS` | 16 | cpp.h | Maximum macro parameters |
| `MAXSYMLEN` | 16 | cpp.h | Symbol buffer size (15 chars + null) |
| Identifier | 14 | — | C-level limit (object file: 15 with `_` prefix) |
| `GROWSTEP` | 16 | cpp.h | Token buffers grow by this, never doubling |
| `SZQ_MAX` | 22 | cpp.h | Fold replay queue; a bail replays all of it |
| `CFSV_MAX` | 21 | cfold.c | Longest expression a fold will attempt |
| `PARAM_MAX` | 16 | knr.c | K&R parameters per function |
| `MAX_INCLUDES` | 32 | cpp.c | `-I` directories |
| `INTERN_HASH` | 63 | util.c | Intern-pool hash buckets |
| id space | 14 bits | util.c | Interned ids; overflow is fatal, not wrapped |

## Memory Management

To minimize BSS for the Z80 target, buffers are allocated dynamically and grow
by `GROWSTEP` rather than doubling — the Z80 build's peak is measured in
hundreds of bytes, and doubling overshoots it.

- **`permalloc` arena** — a bump allocator for objects that are never freed:
  macro definitions, include paths, interned names. cpp is a single-shot tool.
- **intern pool** — one canonical copy of each unique identifier, bounded by
  source vocabulary rather than stream length. Every `tokcpy` is a flat field
  copy; no stage owns a name.
- **`tdq`** — the one pending queue left, holding typedef-expansion output.
  Typedef'd struct bodies stream one member per pull to keep it small.
- **tokarrays** — the walker's collection buffers (`cond_a`, `init_a`, a
  `for`'s increment). Only the increment outlives a body, and it lives in
  `do_for`'s own frame, so nested loops save and restore nothing.

Recursion depth is statement nesting, and those frames are smaller than the
context stacks the filter pipeline used to keep. `poolstats()` (DEBUG builds)
prints the live-byte high-water mark across every buffer — that peak is the
number that has to fit in the Z80's gap.

# Debug Support

When compiled with `-DDEBUG`, verbose output controlled by `VERBOSE()` macro.
The flags are generated by `makedebug.sh`, which scans the sources for
`VERBOSE(...)` uses and assigns bits in sorted order — so adding a use adds a
flag, and the bit values are not stable across such a change:

| Flag | Description |
|------|-------------|
| V_CPP | Preprocessor directives |
| V_FILTER | Normalizer token flow |
| V_IO | Character stream I/O |
| V_MACRO | Macro expansion |
| V_STR | String parsing |
| V_SYM | Symbol recognition |
| V_TOKEN | Token recognition |

DEBUG builds also call `poolstats()` at exit, printing macro/intern/buffer
occupancy and the buffer high-water mark.

# Known Limitations

1. **Macro text restrictions** - Values typically single tokens (more restrictive than standard cpp)
2. **Function-like detection** - `(` must immediately follow name, no whitespace
3. **No floating point** - `float`/`double` are not keywords at all (a program
   may typedef them), and a float *literal* is scanned, rejected with
   `ER_C_CD`, and yields 0
4. **`signed` is lexed but must not be used** - it is a keyword so headers
   parse; project code may not use it (see `../RESTRICTIONS.md`)
5. **Enum constants are global** - lowered to macro-table entries, so a
   constant's name may not be reused as any other identifier later in the file
6. **Nested comments** - Not supported (first `*/` closes)

# Integration with Compiler

The preprocessor produces:
- `.x` file: binary lexeme stream consumed by pass1 (always written)
- `.n` file: id-to-name sidecar for the interned identifiers (always written).
  pass1 never needs the spellings — its lookups are 16-bit compares. pass2
  reads the sidecar to spell symbols in assembly, and the driver uses it to
  translate `@{id}` markers in the passes' diagnostics.
- `.i` file: human-readable form for debugging, produced on demand by decoding
  `.x` with `xdump` (`-p` writes it, `-E` dumps it to stdout)

Token encoding designed for:
- Minimal size (raw binary, no ASCII-hex expansion; identifiers are 2-byte ids)
- Fast parsing (fixed-format fields, token codes shared via `lexeme.h`)
- Embedded nulls in strings (counted format)

# Testing

- `make test` — language-conformance sweep (`langtest`) followed by the
  filter/loop-lowering suite (`test/runtest.sh`).
- `make langtest` — the self-compile contract: every file in `SOURCES` is
  linted against the input language ([INPUT.md](INPUT.md), `validate_src.py`),
  preprocessed with `-DCCC`, and the resulting `.x`/`.i` checked against the
  output language ([OUTPUT.md](OUTPUT.md), `validate_x.py` wire format +
  normalized grammar, `validate_i.py`). Failures leave details in
  `langtest/<file>.err`.
- `make regression` — byte-exact baseline harness (`tests/regress.sh`).
- `make valgrind` — runs the host cpp over its own sources under valgrind,
  failing on definite/indirect leaks and invalid reads/writes. Logs for
  failing files are kept in `valgrind/<base>.vg`.
- `abdiff.sh save | check` — tree-wide byte-identity gate: holds every
  source's `.x`/`.n`/`.s` byte-identical across a change. Anything that moves
  a synthesis point in the walker shows up here first.
- `test/sweep.sh` (part of `make test`) — input-phase invariance: shifts
  a construct-rich payload through all 512 phases of the input-buffer
  block; output must be byte-identical at every phase.  Catches
  position-dependent lexer/refill bugs.
- `test/runtest.sh -g` regenerates the expected outputs after an intentional
  change to lowering shapes or `xdump` rendering.
